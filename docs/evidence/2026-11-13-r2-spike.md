# R2 trial: the installed app runs its own engine and Node (13 Nov 2026)

- **When and who:** 13 Nov 2026, 10:45–11:15 UK, Claude in the cloud.
- **Where:** Linux container. Windows is checked by CI (`checks`, Windows job, last two steps).
- **How the app was started:** it was not. No installer was built: that is stage R5.

## What was built

| Part | What it does |
| --- | --- |
| `toolchain.json` | Pins Node 24.22.3 for `win-x64` (and `linux-x64` for checks here), with the SHA-256 from nodejs.org's SHASUMS256.txt. |
| `scripts/bundle-engine.mjs` | Builds the engine, packs it with its production packages only (plain folders, no links), downloads Node once, refuses it if the SHA-256 differs, and copies only `node(.exe)`. |
| `scripts/smoke-bundle.mjs` | Starts the packed engine with the packed Node, as the app does, and asks for ping, settings_check and environment_check. |
| `src-tauri/src/engine.rs` | Looks next to the app's own program for `engine/dist/helper.js` and `node/node.exe` first. Puts the bundled Node's folder first on PATH for the engine, so builds use the same Node. Dev mode and `AIP_ENGINE` work as before. |
| `src-tauri/tauri.bundle.conf.json` | For the installer build only (stage R5): copies the two folders next to the app's program. Not used by `tauri dev`. |

## Found in this trial

1. **Licence (must be checked in R6).** The Agent SDK's program says "© Anthropic PBC. All rights reserved. Use is subject to the Legal Agreements" (code.claude.com/docs/en/legal-and-compliance). Shipping it inside an installer that companies license is redistribution. It needs a check of Anthropic's terms before any installer goes to a company. Until then, nothing is sent out.
2. Two engine features read the app's source folder and will not work as before from an installed app: "look for updates" (`engine/src/updates.ts` runs `pnpm outdated` in the source folder) and the app's own pins in `engine/src/environment.ts` (falls back to "pnpm 10, Node 22+"). They don't crash. To be decided in R3.
3. pnpm and git are not bundled yet (R3), so the environment check still says "pnpm isn't installed" when the PC has none.

## What this does not show

- That the real Windows installer installs and starts: no installer was built (R5).
- That a build (which runs the Agent SDK's program, pnpm and git) works from an installed app: needs R3 and a key.
- Windows behaviour, except what the CI step checks.
